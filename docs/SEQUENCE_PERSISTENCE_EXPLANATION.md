# Sequence Number Persistence & Generation Explained

## Overview

The application uses a **database-persisted sequence number system** with **daily precision** that automatically resets each day. Numbers are generated in sequence and stored in the `SequenceGenerator` table.

## Database Model: SequenceGenerator

```prisma
model SequenceGenerator {
  id           Int      @id @default(autoincrement())
  entityType   String   // Entity type (HEALTH_ASSESSMENT, CONSULTATION, EKAS_TRANSACTION, etc.)
  clinicId     Int?     // Clinic ID (null for personal records)
  date         String   // Format: "YYYYMMDD" for day precision
  currentValue Int      @default(0)
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt
  Clinic       Clinic?  @relation(fields: [clinicId], references: [id], onDelete: Cascade)

  @@unique([entityType, clinicId, date])  // Ensures one sequence per entity/clinic/day
  @@index([clinicId, date])
  @@index([date])
}
```

**Key Design:**

- **Composite Unique Index**: `(entityType, clinicId, date)` ensures exactly one sequence counter per entity type, per clinic, per day
- **Day Precision**: Date stored as `YYYYMMDD` string (e.g., "20260112" for January 12, 2026)
- **Auto-Reset**: New day = new row with `currentValue: 1`
- **Clinic-Scoped**: `clinicId` can be null for personal health records (HAF), or clinic-specific for consultation tickets

## How Numbers Are Generated

### 1. Case Numbers (Health Assessment & Consultation)

**Generated by**: `generateTimestampCaseNumber(entityType, clinicId?, options?)`

**Location**: `src/services/sequence-generator.service.ts:110`

**Flow**:

```typescript
// Get today's date in YYYYMMDD format
const dateKey = getDateKey(date); // e.g., "20260112"

// Atomic transaction ensures consistency
const sequence = await prisma.$transaction(async (tx) => {
  // Try to find today's sequence
  let seq = await tx.sequenceGenerator.findFirst({
    where: {
      entityType,        // "HEALTH_ASSESSMENT" or "CONSULTATION"
      clinicId: clinicId ?? null,
      date: dateKey,     // "20260112"
    },
  });

  // If doesn't exist, create starting at 1
  if (!seq) {
    seq = await tx.sequenceGenerator.create({
      data: {
        entityType,
        clinicId: clinicId ?? null,
        date: dateKey,
        currentValue: 1,  // First number of the day
      },
    });
    return seq;
  }

  // Increment the counter
  return await tx.sequenceGenerator.update({
    where: { id: seq.id },
    data: { currentValue: { increment: 1 } },
  });
});
```

**Output Format**:

```
CONS-20260112-00001  (First consultation of Jan 12, 2026)
CONS-20260112-00002  (Second consultation of Jan 12, 2026)
HAFT-20260112-00001  (First health assessment of Jan 12, 2026)
```

### 2. Transaction & Auth Numbers (EKAS)

**Generated by**: `getNextSequenceNumber(entityType, clinicId, date?)`

**Location**: `src/lib/sequence-generator.ts:168`

**Flow**: Same as case numbers but returns raw numeric sequence (formatted separately)

**Output Format**:

```
EKAS-C123-20260112-000001  (Clinic 123 transaction)
EKAS-20260112-000001       (Personal transaction)
PHK-C123-20260112-000001   (Clinic 123 auth code)
PHK-20260112-000001        (Personal auth code)
```

## Persistence Mechanism

### Transaction Safety

Each generation uses `prisma.$transaction()` to ensure:

- **Atomicity**: Read-Modify-Write happens as one unit
- **Isolation**: No concurrent duplicates across requests
- **Consistency**: Sequence counter always accurate

### Daily Reset

```
Date Changes → New YYYYMMDD Key → New SequenceGenerator Row Created
Jan 11: { entityType: "CONS", clinicId: 5, date: "20260111", currentValue: 47 }
Jan 12: { entityType: "CONS", clinicId: 5, date: "20260112", currentValue: 1 }  ← Auto-reset
```

### Clinic-Scoped Sequences

- **Personal Records** (HAF): `clinicId = null`
- **Clinic Consultation**: `clinicId = [clinic_id]`
- Each clinic gets its own daily sequence counter

## Current Usage in Application

### Case Numbers

```typescript
// Health Assessment Form (HAF)
const caseNumber = await generateTimestampCaseNumber("HEALTH_ASSESSMENT");
// Result: "HAFT-20260112-00001"

// Consultation Ticket
const caseNumber = await generateTimestampCaseNumber("CONSULTATION", clinicId);
// Result: "CONS-20260112-00001"
```

### Transaction Numbers

```typescript
const transactionSeq = await getNextSequenceNumber('EKAS_TRANSACTION', clinicId);
const transactionNumber = formatTransactionNumber(clinicId, transactionSeq);
// Result: "EKAS-C123-20260112-000001" or "EKAS-20260112-000001"

const authSeq = await getNextSequenceNumber('EKAS_AUTH_CODE', clinicId);
const authCode = formatAuthorizationCode(clinicId, authSeq);
// Result: "PHK-C123-20260112-000001" or "PHK-20260112-000001"
```

## Limits & Constraints

| Parameter | Case Numbers | Transaction/Auth |
|-----------|-------------|------------------|
| Sequence Digits | 5 digits | 6 digits |
| Max Per Day | 99,999 | 999,999 |
| Format | `PREFIX-DATE-SEQUENCE` | `PREFIX-DATE-SEQUENCE` or `PREFIX-CLINIC-DATE-SEQUENCE` |
| Reset | Every day @ midnight | Every day @ midnight |

## Error Handling

If daily sequence exceeds limit:

```
SequenceGenerationError: 
  Sequence limit exceeded for HEALTH_ASSESSMENT on 20260112: 99999/99999
```

**Recovery**: Manual sequence reset (very unlikely in practice)

## Database Queries During Generation

1. **FindFirst**: Check if today's sequence exists (indexed by `[clinicId, date]`)
2. **Create** or **Update**: Atomic increment
3. **Total Queries per Generation**: 2-3 (within single transaction)

## Summary

| Aspect | Implementation |
|--------|-----------------|
| **Persistence** | Database table `SequenceGenerator` |
| **Day Precision** | YYYYMMDD string format |
| **Daily Reset** | Composite unique index creates new row per day |
| **Concurrency Safety** | Prisma transactions + database unique constraint |
| **Clinic Scoping** | Separate sequence per clinic (or null for personal) |
| **Series Increment** | Atomic increment operation in transaction |
| **Format** | Formatted after generation: `PREFIX-DATE-SEQUENCE` |
